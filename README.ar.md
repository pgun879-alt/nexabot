# NexaBot

**منصّة مساعد ذكي وأتمتة، مبنيّة كـ modular monolith بمعمارية نظيفة —
بـ Python 3.11+ و FastAPI و SQLAlchemy 2 async و Alembic.**

[English README ←](README.md)

---

## ما هذا المشروع

تيليجرام *واجهة* من الواجهات، وليس حدّ المنتج. منطق المجال (domain) ومنطق
التطبيق مستقلّان تماماً عن أي آلية تسليم، بحيث تستطيع واجهة HTTP ولوحة تحكّم
وعمّال خلفية وبوت تيليجرام أن تعمل جميعها على النواة نفسها.

هذا المستودع هو **الأساس**: المعمارية، طبقة الحفظ، مسار تنسيق الوكيل الذكي،
والانضباط الهندسي حولها. وهو عمداً ليس منتجاً مكتملاً — و[قسم الحالة](#الحالة)
يوضّح بدقّة ما هو موجود وما هو غير موجود.

## ما الذي يُبرزه المشروع

كل ادّعاء أدناه يمكن التحقّق منه في الكود، مع الإشارة إلى الملف.

| | |
|---|---|
| **طبقات مفروضة فعلياً** | `domain` لا يعتمد على شيء؛ `application` يعتمد على domain و ports؛ `infrastructure` ينفّذ الـ ports. لا يظهر أي نوع من SQLAlchemy أو FastAPI أو SDK مزوّد فوق طبقة البنية التحتية. |
| **حدود معاملات صحيحة** | استدعاء نموذج اللغة يتم **دون أي معاملة قاعدة بيانات مفتوحة** — وحدة عمل تحفظ الطلب، وأخرى تحفظ النتيجة. [`use_cases.py`](src/nexabot/application/agent/use_cases.py) |
| **سلامة التزامن** | الـ idempotency يستخدم رمز مطالبة (claim token) مع تسوية compare-and-swap، فالعامل الذي انتهت صلاحية مطالبته واستُولي عليها لا يستطيع الكتابة فوق نتيجة المحاولة الأحدث. [`idempotency.py`](src/nexabot/infrastructure/database/repositories/idempotency.py) |
| **الثوابت في قاعدة البيانات** | قيود CHECK تعكس كيانات المجال — الحالات الصالحة، الميزانيات الموجبة، اكتمال الحالة النهائية — فلا يستطيع backfill خاطئ إنشاء حالة يعتبرها المجال مستحيلة. [`models.py`](src/nexabot/infrastructure/database/models.py) |
| **ترحيلات مُختبَرة فعلاً** | السلسلة تُطبَّق صعوداً ثم تُعكَس إلى الأساس ثم تُطبَّق مجدّداً داخل CI، والمخطّط الناتج يُقارَن بـ metadata النماذج. أي انحراف يُسقط البناء لا النشر. [`test_migrations.py`](tests/integration/test_migrations.py) |
| **حدود موارد حقيقية** | مهلات محدودة لاستدعاء النموذج، وميزانية *توكِنات* (لا عدد رسائل)، وسقف لحجم المدخلات، ونوافذ تاريخ مُصفّحة. |
| **أخطاء لا تُسرّب** | تصنيف أخطاء مجال مُنمَّط ومربوط بـ HTTP. نص استثناء المزوّد لا يُحفظ ولا يُعاد أبداً، وبيانات الاعتماد تُزال من روابط الاتصال في السجلّات ومخرجات الإعدادات. |
| **الأمان افتراضياً** | حدّ المصادقة في HTTP **يرفض افتراضياً**: المسار غير قابل للوصول حتى تُربط مصادقة حقيقية، بدل أن يكون مفتوحاً بصمت. لم تُكتب مصادقة وهمية. [`security.py`](src/nexabot/interfaces/api/security.py) |

## المعمارية

قاعدة الاعتماد أحادية الاتجاه: **لا شيء يعرفه المجال يمكن أن يشير إلى الخارج.**

```text
interfaces  ──→  application  ──→  domain
                      │              ↑
                      └──→  ports  ──┘
                              ↑
                      infrastructure

bootstrap  ·······→  يربط كل شيء (wiring فقط)
```

المواصفة الكاملة: [`docs/architecture/architecture.md`](docs/architecture/architecture.md) ·
سجلّ القرار: [`docs/architecture/adr/0001-modular-monolith-clean-architecture.md`](docs/architecture/adr/0001-modular-monolith-clean-architecture.md)

## البدء السريع

<div dir="ltr">

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -e ".[dev]"
```

</div>

تشغيل بوابة الجودة كاملة — دون قاعدة بيانات أو Docker أو شبكة:

<div dir="ltr">

```bash
pytest -q && ruff check . && mypy src migrations
```

</div>

لتشغيل الـ API مقابل PostgreSQL:

<div dir="ltr">

```bash
cp .env.example .env   # ثم اضبط DATABASE_URL
alembic upgrade head && nexabot-api
```

</div>

`DATABASE_URL` يستخدم مُشغّلاً غير متزامن، لذا يعمل Alembic عبر محرّك async —
المحرّك المتزامن فوق `postgresql+asyncpg` يفشل عند أول استعلام. ملف
`alembic.ini` لا يحمل أي رابط عمداً؛ `migrations/env.py` يستخرجه من الإعدادات
حتى لا يبقى في المستودع أي قيمة تشبه بيانات اعتماد.

نقاط الفحص: `GET /health/live` (العملية تعمل) و `GET /health/ready`
(الاعتماديات متاحة — 200 أو 503). تفاصيل الجاهزية مقتضبة عمداً
(`ok` / `timeout` / `unavailable`) لأن أخطاء المُشغّل تقتبس رابط الاتصال كاملاً.

## الاختبارات

**143 اختباراً**، جميعها دون اتصال. تعمل مقابل SQLite في الذاكرة عبر
`aiosqlite`؛ والمستودعات مكتوبة بـ SQLAlchemy Core/ORM قياسي دون أي سلوك خاص
بـ PostgreSQL، لذا يُختبَر التعيين والاستعلام والمعاملات والقيود بالكامل.

الاختبارات مبنيّة حول الانحدارات (regressions) لا حول نسبة التغطية:

- سلسلة الترحيل صعوداً ← نزولاً ← صعوداً، مع فحص انحراف مقابل metadata النماذج
- قيود CHECK يتم التحقق منها بإدخال صفوف يعتبرها المجال مستحيلة
- دورة حياة مطالبة الـ idempotency: المالك الأصلي، انتهاء الصلاحية، الاستيلاء،
  رفض تسوية المالك القديم، السجلّات المُسوّاة مسبقاً، والمطالِبون المتزاحمون
- دورة الوكيل: الملكية، فرض المهلة على مزوّد مُعلَّق عمداً، تقليم ميزانية
  التوكِنات، المدخلات المفرطة، تعمية أخطاء المزوّد، والتسوية في كل مسار فشل
- حدّ المصادقة: المسارات المحميّة غير قابلة للوصول دون authenticator مربوط

> **لم يُختبَر، ولا يُدَّعى أنه اختُبر:** PostgreSQL و Redis ومزوّدو نماذج
> حقيقيون و Docker. لا يتوفّر أيٌّ منها في بيئة التطوير. كل ما سبق يعمل على
> SQLite. هذا التمييز مذكور صراحةً لا مطموس عمداً.

## الحالة

<a name="الحالة"></a>

**منفَّذ** — إعدادات مُتحقَّق منها تفشل مبكراً؛ تصنيف أخطاء المجال مربوط بـ
HTTP؛ تسجيل مُهيكل مع تعمية الأسرار وسياق تتبّع مربوط بكل طلب؛ نقاط فحص صحّة
مع فحص جاهزية محدود بمهلة؛ ترحيلات بثوابت مفروضة من قاعدة البيانات؛ مستودعات
للهوية والمحادثات وتشغيلات الوكيل والـ idempotency؛ تحميل محادثات محدود؛
idempotency برموز مطالبة؛ مسار `RunAgentTurn` كاملاً؛ إغلاق رشيق.

**منفَّذ جزئياً** — ميزانية التوكِنات تُفرَض مقابل *تقدير* متحفّظ لا مُجزِّئ
حقيقي (لا يوجد محوّل مزوّد ليقدّمه)؛ تسوية التشغيل تغطي كل مسارات الخروج داخل
العملية لكن ليس موت العملية؛ سياق التتبّع مربوط بطلبات HTTP فقط.

**مخطَّط** — طابور Redis، محوّلات مزوّدي نماذج حقيقية، تخزين ملفات، سجلّ/منفّذ
الأدوات، فرض الحصص، سجلّ التدقيق، تحديد المعدّل، معالجة الملفات، وواجهة
تيليجرام.

**حواجز معروفة قبل خدمة حركة حقيقية** — لا توجد مصادقة HTTP (الحدّ موجود ويرفض
افتراضياً، لكن لم يُختَر نموذج اعتماد بعد)؛ لا يوجد محوّل مزوّد نماذج غير
الـ stub الحتمي؛ لا يوجد reaper للتشغيلات التي قطعها موت العملية؛ لا تحديد
معدّل؛ لم يُتحقَّق بعد مقابل PostgreSQL.

> ذكر الحواجز في README لمشروع عرض أعمال خيار متعمّد. البرمجيات التي تدّعي
> الجاهزية للإنتاج وهي ليست كذلك تكلّف أكثر بكثير من برمجيات تقول أين تقف.

## بنية المشروع

<div dir="ltr">

```text
src/nexabot/
├── domain/          الكيانات، آلات الحالة، الثوابت، تصنيف الأخطاء
├── application/     حالات الاستخدام، التنسيق، حدود المعاملات
├── ports/           البروتوكولات التي تنفّذها طبقة البنية التحتية
├── infrastructure/  SQLAlchemy، Alembic، محوّلات النماذج
├── interfaces/      تطبيق FastAPI، الصحّة، الوسطاء، حدّ الأمان
├── config/          إعدادات مُتحقَّق منها
├── observability/   تسجيل مُهيكل، سياق تتبّع
└── bootstrap/       ربط الاعتماديات، نقاط دخول العمليات
```

</div>
